# onair-collector

Cron-driven scraper worker for [onair-stack](../readme.md). Fetches public IPTV
playlists, broadcaster APIs and EPG feeds, normalizes and verifies the records, and
writes them to Postgres. Exposes **no HTTP server** (no ingress/egress).

## Layout

```
src/
  main.ts                  # entrypoint: cron scheduler or RUN_ONCE pass
  config/index.ts          # zod-validated env (cron, timeouts, TZ)
  db/
    client.ts              # Prisma postgres client (contract-driven)
  collectors/
    base.collector.ts      # BaseCollector: name, schedule, enabled, collect(), run()
    stream/
      index.ts             # StreamCollector: m3u playlists + famelack ingest
      iptv.collector.ts    # per-playlist fetch -> geo-block filter -> verify
      famelack.collector.ts# zod-validated famelack JSON (HLS + YouTube embeds)
      broadcast.collector.ts# broadcastatlas channels -> verify -> streams
      stream-health.collector.ts # re-verify saved streams, delete dead links
    schedule/
      usa.schedule.ts      # online-television.com daily programme list
      uk.schedule.ts       # freely.co.uk TV guide API
      uk.sports.scheduler.ts# XMLTV EPG (zappscore)      
      source/uk.sports.channels.json
  matchers/
    bein.matcher.ts        # stricter (0.99) matcher for beIN channels
  jobs/
    registry.ts            # add new collectors here
    scheduler.ts           # node-cron wiring, overlap guard, runOnce()
  prisma/
    contract.prisma        # shared schema (same file as in ../onair)
    contract.json          # generated by `prisma contract emit`
    channels.ts            # one-off channel bootstrap script
  utils/
    http.ts                # fetchJson/fetchHtml with timeout + UA + retry
    retry.ts               # exponential backoff helper
    url.ts                 # verifyM3U8, resolution tiers
    urlparser.ts           # parseM3U
    eguide.parser.ts       # parseEpg (XMLTV)
    image.ts               # Cloudinary upload straight from a URL
    logger.ts              # pino
    sentry.ts              # Sentry helpers (no-op without a DSN)
    instrument.ts          # Sentry init
```

## Jobs

Registered in `src/jobs/registry.ts`; cron expressions are evaluated in `TZ` (default
`UTC`).

| Job | Cron | Source | What it does |
| --- | --- | --- | --- |
| `StreamHealth` | `*/30 * * * *` (override with `STREAM_HEALTH_CRON`) | saved `Stream` rows | Re-verifies stored links, deletes dead ones, refreshes resolutions. Keeps transient failures, skips YouTube embeds, trips a safety stop when too many links look broken. |
| `Schedule` | `15 01 * * *` | `online-television.com/tv-channel/<externalId>/?pgday=YYYY-MM-DD` | Scrapes the daily programme list per channel and inserts `Schedule` rows. |
| `StreamCollector` | `0 */6 * * *` | ~150 public m3u playlists + `famelack-data` | Fetches, filters geo-blocked entries, verifies every m3u8, fuzzy-matches names to channels and upserts `Stream` rows. |
| `uk.schedule` | `15 02 * * *` | `freely.co.uk/api/tv-guide` | Upserts UK channels and their programmes. |
| `Broadcast` | `0 */4 * * *` | `broadcastatlas.com/api/channels/ranked` | Pages through ranked UK/US channels, verifies playback options and creates `Stream` rows. |
| `Bein Schedule` | `00 03 * * *` | `beinsports.com/api/opta` | Upserts beIN channels (`USA`/`MENA`) and their programmes. |
| `UK Sports Schedule` | `30 01 * * *` | `zappscore.com/epg/api/epg.xml` | Parses the XMLTV EPG per channel and writes `SPORTS` channels and programmes. |
| `ScheduleCleanup` | `0 4 * * *` (override with `SCHEDULE_CLEANUP_CRON`) | `schedule` rows | Deletes programmes whose `endTime` is older than `SCHEDULE_RETENTION_DAYS` (default 4). |

`StreamHealth` is registered first so a `RUN_ONCE` pass prunes dead links before the
ingest collectors re-add working ones.

## Add a source

1. Duplicate a collector under `src/collectors/stream/` or `src/collectors/schedule/`
   and set `name`, `schedule`, plus the zod schema / cheerio selectors / API call.
2. Register it in `src/jobs/registry.ts`.
3. Set `enabled = false` on the class to park the job without removing it.

## Run

```bash
cp .env.example .env
npm install
npm run dev            # long-running scheduler
npm run dev:once       # RUN_ONCE=true: run all enabled jobs once and exit
npm run build && npm start
npm run start:once     # production one-shot (K8s CronJob)
```

Deploy `start:once` as a Kubernetes CronJob if you prefer external scheduling over
in-process cron. A `RUN_ONCE` run exits non-zero when a job fails.

Config (env): `DATABASE_URL`, `NODE_ENV`, `RUN_ONCE`, `TZ`, `LOG_LEVEL`, `HTTP_TIMEOUT_MS`,
`HTTP_MAX_RETRIES`, `HTTP_USER_AGENT`, `STREAM_HEALTH_CRON`, `STREAM_HEALTH_BATCH_SIZE`,
`STREAM_HEALTH_TIMEOUT_MS`, `STREAM_HEALTH_DEEP_CHECK`, `STREAM_HEALTH_MAX_DELETE_RATIO`,
`SCHEDULE_CLEANUP_CRON`, `SCHEDULE_RETENTION_DAYS`,
`SENTRY_DSN`, `SENTRY_ENVIRONMENT`, `SENTRY_TRACES_SAMPLE_RATE`, `CRONITOR_API_KEY`,
`CRONITOR_ENVIRONMENT`, `CRONITOR_REGION`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`,
`CLOUDINARY_API_SECRET`. See [`.env.example`](.env.example) for the full list and defaults.

> Cronitor is optional: with no `CRONITOR_API_KEY` the plain `node-cron` scheduler is used
> and no ping is sent. Jobs are toggled with the `enabled` flag on the collector class,
> not with an env var.

## DB

Same Prisma 8 contract pattern as `onair`: define tables in `src/prisma/contract.prisma`,
run `npx prisma contract emit` to regenerate `contract.json` + `contract.d.ts`, then use
the generated client through `src/db/client.ts`.

To create the tables in an empty database, run `npx prisma db init` (additive and
idempotent). The `migrate` stage of the `Dockerfile` does exactly that — the compose
file at the repository root runs it as a one-shot job before the services start.
